# PanLayer Firecrawl 早参失败兜底设计

## 目标

在不改变 PanLayer 页面结构、五模块早参框架和行情指标口径的前提下，为早参模块增加 Firecrawl 自动失败兜底。当 Qwen 因超时、来源不足、必需词缺失或响应结构不合格而失败时，服务端使用 Firecrawl 搜索并抓取相关来源，再由 Qwen 基于该来源包纠错重写。

Firecrawl 只负责新闻与产业资料的发现和正文提取，不提供指数、汇率、利率、商品或个股报价。所有数值仍以现有服务端行情快照为唯一依据。

## 方案选择

采用“自动失败兜底”：

1. Qwen 按现有流程首次生成模块。
2. 首次生成失败且剩余任务预算足够时，服务端为该模块执行一次 Firecrawl 搜索。
3. 服务端清洗、筛选并压缩搜索结果，形成带固定来源 ID 的只读资料包。
4. Qwen 第二次生成时关闭自身联网搜索，只能使用 Firecrawl 资料包和服务端行情快照。
5. 第二次结果继续经过现有来源、必需词、结构、行情数字和禁止荐股校验。
6. 第二次仍失败时保留失败状态与安全化错误原因，不使用旧内容冒充最新内容。

不采用每天为全部模块预先调用 Firecrawl，以控制延迟和额度；也不局限于手动按钮，定时任务和手动任务共用同一兜底逻辑。

## 组件边界

### Firecrawl 搜索客户端

新增独立的 TypeScript 客户端模块，只负责：

- 根据稳定查询参数调用 Firecrawl `/search`；
- 使用 `FIRECRAWL_API_KEY` 进行服务端认证；
- 限制搜索结果数量为 5；
- 请求新闻和网页结果，并获取用于模型纠错的正文内容；
- 对请求头、响应正文和 JSON 解析应用统一超时；
- 返回与模型无关的标准来源对象。

客户端不访问数据库、不调用 Qwen，也不决定模块是否需要兜底。

### 来源包构建器

根据模块日期、标题、必需词生成查询。查询必须包含：

- 北京时间日期；
- 模块固定标题；
- 模块必需词；
- “A股隔夜早参”语境。

来源包执行以下处理：

- 只接受 `http` 或 `https` URL；
- 按规范化 URL 去重；
- 排除社交平台、论坛、搜索跳转页和没有正文的结果；
- 优先保留监管机构、交易所、公司公告、官方统计及主流财经媒体；
- 清除控制字符和网页指令性文本；
- 每个来源正文截断，整个来源包设置总字符上限；
- 为来源生成稳定的 `firecrawl_<module>_<n>` ID；
- 保留标题、URL、可验证发布时间和北京时间获取时间。

Firecrawl 返回内容一律视为不可信数据，只能放入明确的数据边界中，不能被当作系统指令执行。

### Qwen 纠错生成

现有 Qwen 生成器增加可选的外部来源包参数。提供 Firecrawl 来源包时：

- 关闭 DashScope 原生联网搜索；
- 在提示词中明确列出允许引用的来源 ID；
- 要求每个事实内容块引用至少一个来源 ID；
- 禁止引用资料包以外的 URL 或来源 ID；
- 继续使用服务端行情快照约束所有市场数字；
- 继续执行五模块必需词、内容长度、排名隔离和不荐股规则。

现有来源验证逻辑负责拒绝不存在的 Firecrawl 来源 ID。通过验证的 Firecrawl 来源与 Qwen 原生搜索来源使用相同的 `BriefSource` 页面模型，因此前端无需修改。

## 运行流程与时间预算

每个模块最多执行：

1. Qwen 首次请求：上限 28 秒；
2. Firecrawl 搜索与正文获取：上限 10 秒；
3. Qwen 纠错请求：上限 28 秒。

兜底开始前必须确认批次剩余预算足以覆盖 Firecrawl 与一次 Qwen 请求，并预留持久化时间。整批任务继续受 110 秒绝对截止时间约束，低于 180 秒任务租约回收窗口。

同一模块每次任务最多调用一次 Firecrawl。多模块仍按现有并发上限执行；达到截止时间后，未完成模块写入失败状态，不阻塞已经成功模块的保存。

## 配置与安全

- 新增生产环境变量 `FIRECRAWL_API_KEY`，在 Sites 中以 secret 保存。
- 可选 `FIRECRAWL_API_URL` 仅用于自托管兼容，默认使用 Firecrawl 托管 API。
- Key 不写入源码、`.env.example` 的值、数据库、错误信息或客户端响应。
- 未配置 Firecrawl Key 时，系统保持现有 Qwen 行为，并记录“Firecrawl fallback unavailable”安全诊断。
- 日志只记录模块、阶段、耗时、结果数量和安全化错误类型，不记录正文或鉴权信息。

## 数据与页面

不新增前端布局或交互。成功兜底后的模块仍显示“完整”，详情抽屉继续展示正文和可点击来源。

来源标题、URL、发布时间和获取时间继续写入现有早参来源数据。无需生成新的历史页面或修改已有数据库表；如果现有来源记录包含来源提供方字段，则标记为 `firecrawl`，否则通过来源 ID 前缀识别。

## 错误处理

以下错误允许触发 Firecrawl：

- Qwen 请求超时；
- Qwen 搜索来源为空或引用不可验证；
- 模块必需词覆盖不足；
- Qwen JSON 或内容块结构校验失败；
- 内容长度不足且现有补写仍未通过。

以下情况不触发或立即停止兜底：

- 任务租约失效；
- 批次剩余时间不足；
- 用户取消或请求已中止；
- Firecrawl Key 未配置；
- Firecrawl 返回空结果；
- Firecrawl 来源全部因 URL、正文或质量规则被过滤。

Firecrawl 或第二次 Qwen 失败不会覆盖原始安全诊断；最终错误同时保留首轮失败类型和兜底失败类型，但必须经过现有脱敏器。

## 测试与验收

### 单元测试

- 查询包含日期、模块标题与全部必需词；
- Firecrawl Key 只进入请求头，不进入错误或返回模型；
- URL 校验、去重、来源排序、正文截断和总字符上限；
- 社交平台、搜索跳转和空正文结果被过滤；
- 超时覆盖响应头、正文读取和 JSON 解析；
- Firecrawl 来源 ID 可被 Qwen 引用，未知 ID 被拒绝；
- 使用 Firecrawl 来源时关闭 Qwen 原生搜索；
- 成功模块不调用 Firecrawl；
- 失败模块最多调用一次 Firecrawl；
- 未配置 Key、空结果和截止预算不足时安全降级；
- 定时批量仍满足 110 秒截止与 180 秒租约不变量。

### 生产验收

1. 使用模拟首轮覆盖不足触发兜底，确认 Firecrawl 与 Qwen 纠错各执行一次。
2. 确认最终模块状态为“完整”，所有事实内容块都有可点击来源。
3. 确认页面没有新增布局变化。
4. 确认普通成功任务不消耗 Firecrawl 调用。
5. 在生产环境手动重试一个失败模块，验证任务在截止时间内完成。
6. 检查 Worker 日志中不包含 Firecrawl Key 或抓取正文。

## 非目标

- 不使用 Firecrawl 替代行情、ETF K 线或国内市场统计接口；
- 不为所有模块固定调用 Firecrawl；
- 不新增用户可见的搜索入口；
- 不改变五模块早参固定结构；
- 不降低来源、数字一致性和不荐股校验。
