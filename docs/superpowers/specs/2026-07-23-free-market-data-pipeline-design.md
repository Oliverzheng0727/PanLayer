# PanLayer 低成本多源行情与全球隔夜数据设计

## 目标与边界

在不购买专业实时行情权限的前提下，为个人私密复盘提供可追溯的 A 股、ETF 与全球隔夜数据。系统优先保证“数据状态真实”，不承诺交易级低延迟，也不把失败、过期或未经核验的数据显示成最新值。

本阶段只用于个人复盘，不用于下单、量化实盘、公开售卖或对外分发行情。未来变为公开或商业产品时必须重新确认行情授权。

## 已选数据源

### 国内行情层

- 盘中主源：东方财富公开行情接口。
- 盘中交叉校验与降级源：腾讯行情公开接口。
- ETF 目录、分时及历史 K 线：东方财富主源，腾讯最新报价校验。
- 首版不调用 Tushare，不读取 `TUSHARE_TOKEN`，不依赖 Tushare MCP。
- 保留现有 `MarketDataProvider` 接口，新增提供商和质量编排层，页面与数据库读取接口不随数据源变化。

### 全球隔夜层

- Twelve Data 免费档作为海外收盘行情主源，只抓早参需要的核心标的并遵守免费额度。
- Alpha Vantage 免费档作为海外收盘行情备用与抽样复核源；每日请求不得超过免费额度。
- FRED 作为美国国债收益率等官方宏观数据源。
- EIA 作为原油、天然气和能源库存等官方数据源。
- OpenAI Responses API 的 Web Search 只负责带引用的新闻与产业信息，不作为行情数字来源；该部分按实际调用计费。

## 国内数据流程

### 盘前证券池

每天首次成功的东方财富全市场快照刷新沪深京证券池并保存代码、名称、市场、板块与更新时间。若主源不可用，可使用数据库中最近一次成功的证券池调用腾讯，但页面必须显示证券池日期；不得把旧价格当成当天价格。

### 六个盘中节点

09:25、10:00、11:00、13:00、14:00、15:00 执行相同流程：

1. 东方财富获取全市场快照。
2. 腾讯按证券代码分批获取快照，每批最多 60 只，并发最多 4 批。
3. 两个来源分别执行代码去重、ST 剔除、价格合法性和时间新鲜度检查。
4. 对共同代码比较最新价及涨跌方向，计算上涨、下跌、平盘家数差异。
5. 选择合格来源生成该节点市场宽度，并保存质量审计信息。

09:25 使用当时可获取的集合竞价最终价格；如果来源尚未完成更新，重试两次，每次间隔 20 秒。超过 09:27 仍不完整时保存“部分”状态，不回填旧日数据。

### 盘后复盘

- 16:10 使用东方财富收盘快照生成复盘，并同步请求腾讯做收盘交叉校验。
- 收盘涨跌家数、涨跌停、大涨股、连板梯队、热点板块和 ETF 摘要全部记录数据来源与质量状态。
- 120 日新高和历史新高使用东方财富前复权历史 K 线计算；历史 K 线缺失的股票不进入分母，也不补零。
- 同一日期任务重跑只更新原记录，不创建重复历史页面。

## 全球隔夜流程

07:15 早参任务先生成全球数值快照，再把快照作为受信任的结构化上下文传给 OpenAI：

1. 核心标的包括道指、纳指、标普 500、费城半导体、英伟达、美光、美元兑离岸人民币、10 年期美债、WTI/布伦特原油、黄金和铜。
2. Twelve Data 读取可用核心标的；Alpha Vantage 只补缺和抽样复核，确保免费请求额度可控。
3. FRED/EIA 的同周期官方值优先于聚合行情；不同频率数据必须显示统计周期。
4. 两个行情源交易日期一致且价格差异不超过 `max(最小报价单位, 0.2%)` 才标记为“交叉一致”。
5. 富时 A50、纳斯达克金龙等标的若免费源不能稳定识别或日期不一致，显示“数据暂缺”。
6. 每个数值记录 provider、symbol、market_time、received_at、value、previous_close、status 和 message。

早参正文中的市场数字只能引用全球数值快照；新闻事实必须引用 Web Search 返回的真实网页。缺少可靠数据时明确写“未查到可靠更新”。

## 质量规则

每个来源快照记录来源、市场时间、系统接收时间、原始记录数、有效记录数、异常记录数和错误摘要。

国内行情状态固定为：

- `complete`：主源有效覆盖率不低于 95%，交叉源有效覆盖率不低于 90%，市场时间延迟不超过 120 秒，两个来源的涨跌方向一致率不低于 98%，上涨或下跌家数差异不超过 `max(30, 有效股票数×1%)`。
- `partial`：至少一个来源覆盖率不低于 90%，但交叉校验缺失、时间过期或差异超过完整阈值。
- `failed`：所有来源覆盖率均低于 90%，或没有可计算的有效价格。
- `demo`：仅本机演示样本，不能显示为真实数据。

单只证券的价格差异阈值为 `max(0.01 元, 昨收价×0.15%)`。超出阈值的证券计入异常数，但仍保留在来源审计中。

## 提供商与质量组件

- `lib/data/tencent.ts`：代码转换、批量请求、腾讯字段映射，输出标准 `Quote`。
- `lib/data/quality.ts`：覆盖率、新鲜度、价格差异、方向一致率和来源选择的纯函数。
- `lib/data/market-pipeline.ts`：负责重试、并发限制、主备调用和质量决策，不承担指标计算。
- `lib/data/global/twelve-data.ts`：海外行情主源适配器。
- `lib/data/global/alpha-vantage.ts`：海外行情备用适配器。
- `lib/data/global/fred.ts` 与 `lib/data/global/eia.ts`：官方宏观适配器。
- `lib/data/global/reconcile.ts`：全球数值去重、官方优先和双源一致性判断。
- `lib/jobs/runner.ts`：调用行情管线并把业务结果和质量结果写入数据库。

## 数据保存与页面状态

继续使用 `breadth_snapshots`、`daily_reviews` 与 `morning_briefs` 保存业务结果，新增：

### `market_source_audits`

- `trade_date`, `snapshot_time`, `source`
- `market_time`, `received_at`
- `raw_count`, `valid_count`, `invalid_count`
- `coverage_pct`, `direction_agreement_pct`, `breadth_difference`
- `status`, `message`

唯一键为 `(trade_date, snapshot_time, source)`。

### `global_market_snapshots`

- `trade_date`, `symbol`, `provider`
- `market_time`, `received_at`
- `value`, `previous_close`, `pct_change`
- `status`, `message`

唯一键为 `(trade_date, symbol, provider)`。

页面统一展示：数据来源、市场时间、更新时间、完整/部分/失败/演示状态。失败节点显示“数据暂缺”，不显示上一交易日值。数据健康接口同时返回国内、全球、宏观和 AI 四个分区状态。

## 重试、额度与密钥保护

- 普通盘中请求失败后重试两次，间隔分别为 1 秒和 3 秒。
- 腾讯请求分批执行，并发上限 4；单批失败只重试该批。
- Twelve Data 免费档按 8 credits/分钟、800 次/天预算；全球任务每日只运行一次，失败只补缺，不批量轮询。
- Alpha Vantage 每日最多使用 25 次免费请求，只补缺或抽样复核。
- FRED/EIA 每日各请求一次并缓存结果。
- OpenAI 早参同一日期默认只生成一次；手动重跑必须显式确认，并记录调用日志以控制费用。
- `TWELVE_DATA_API_KEY`、`ALPHA_VANTAGE_API_KEY`、`FRED_API_KEY`、`EIA_API_KEY`、`OPENAI_API_KEY` 只存在本机 `.dev.vars` 或 OpenAI 托管环境 Secret 中，不出现在客户端、日志、错误信息或 Git 记录中。
- 任一公开行情接口字段变化时，对应映射测试必须先失败；修复前该来源自动降级为不可用。

## ETF 处理

- ETF 目录与分类每日首次访问时由东方财富刷新并缓存。
- 分时、日 K、周 K、月 K 按需获取，不在后台批量抓取所有 ETF 分钟数据。
- 腾讯只校验当前所选 ETF 的最新价和涨跌幅，避免为全部 ETF 产生大量请求。
- 页面显示“东方财富／腾讯交叉校验”或具体失败原因，不显示 Tushare 相关状态。

## 测试与验收

- 使用固定样本验证东方财富与腾讯字段映射、沪深京代码转换和 ST 剔除一致。
- 验证腾讯批量请求每批不超过 60 只、并发不超过 4。
- 验证国内覆盖率、延迟、价格差异、方向一致率及状态边界。
- 验证主源失败时腾讯可基于已缓存证券池生成“部分”快照，双源失败时不写入旧价格。
- 验证 Twelve Data、Alpha Vantage、FRED 与 EIA 映射及缺少密钥行为。
- 验证全球双源日期不一致、价格超阈值和官方宏观优先规则。
- 验证重复任务只更新同一唯一键，OpenAI 早参不会无确认重复收费。
- 验证任何 API Key 都不出现在渲染 HTML、API 响应、日志及 Git 跟踪文件中。
- 本机固定样本测试、完整构建和受保护 API 验证通过后，再配置真实免费 API Key 上线。

## 实施顺序

先实现国内双源质量管线，再实现全球隔夜数值层和早参注入，随后接入数据库、数据健康状态与页面提示，最后继续执行已经批准的 ETF“我的自选”功能计划。
