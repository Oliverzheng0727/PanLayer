# PanLayer 零成本多源行情管线设计

## 目标与边界

在不购买专业实时行情权限的前提下，为个人私密复盘提供可追溯的 A 股和 ETF 数据。系统优先保证“数据状态真实”，不承诺交易级低延迟，也不把失败、过期或未经核验的数据显示成最新值。

本阶段只用于个人复盘，不用于下单、量化实盘、公开售卖或对外分发行情。未来变为公开或商业产品时必须重新确认行情授权。

## 已选方案

- 盘中主源：东方财富公开行情接口。
- 盘中交叉校验与降级源：腾讯行情接口。
- 盘后权威校正：当前 Tushare Token 已验证可用的 `daily` 和 `stock_basic` 接口。
- ETF 目录、ETF分时及历史K线：东方财富主源，腾讯最新报价校验。
- Tushare MCP 仅供开发和人工查询；网站运行时使用服务端 HTTP API，不依赖 MCP 会话。
- 保留现有 `MarketDataProvider` 接口，新增提供商和质量编排层，页面与数据库读取接口不随数据源变化。

## 数据流程

### 盘前初始化

每天首次任务使用 Tushare `stock_basic` 刷新沪深京上市证券主数据，并缓存当天预期证券数量。若 Tushare不可用，则使用最近一次成功的证券主数据，但明确将“主数据日期”显示在数据健康信息中。

### 六个盘中节点

09:25、10:00、11:00、13:00、14:00、15:00执行相同流程：

1. 东方财富一次获取全市场快照。
2. 腾讯按缓存证券代码分批获取快照，每批最多60只，并发最多4批。
3. 两个来源分别执行代码去重、ST剔除、价格合法性和时间新鲜度检查。
4. 对共同代码比较最新价及涨跌方向，计算两个来源的上涨、下跌、平盘家数差异。
5. 选择合格来源生成该节点市场宽度，并保存质量审计信息。

09:25使用当时可获取的集合竞价最终价格；如果来源尚未完成更新，重试两次，每次间隔20秒。超过09:27仍不完整时保存“部分”状态，不回填旧日数据。

### 盘后校正

- 16:10先用盘中来源生成即时收盘复盘。
- 17:20调用 Tushare `daily` 获取当日全市场正式日线。
- Tushare覆盖率合格时，重新计算收盘涨跌家数、涨跌停、大涨股和新高基础状态，并将复盘标记为“已核验”。
- 如果 Tushare当日数据尚未发布，任务在17:40再重试一次；仍失败则保留16:10结果并标记“部分”。
- 校正任务幂等，同一日期只更新原记录，不创建重复历史页面。

## 质量规则

每个来源快照都记录来源、市场时间、系统接收时间、原始记录数、有效记录数、异常记录数和错误摘要。

状态判断固定为：

- `complete`：主源有效覆盖率不低于95%，交叉源有效覆盖率不低于90%，市场时间延迟不超过120秒，两个来源的涨跌方向一致率不低于98%，上涨或下跌家数差异不超过 `max(30, 有效股票数×1%)`。
- `partial`：至少一个来源覆盖率不低于90%，但交叉校验缺失、时间过期或差异超过完整阈值。
- `failed`：所有来源覆盖率均低于90%，或没有可计算的有效价格。
- `verified`：盘后指标已由 Tushare当日正式日线重新计算。

单只证券的价格差异阈值为 `max(0.01元, 昨收价×0.15%)`。超出阈值的证券不参与交叉一致率，并计入异常数。

## 提供商与质量组件

- `lib/data/tencent.ts`：代码转换、批量请求、腾讯字段映射，输出标准 `Quote`。
- `lib/data/tushare.ts`：服务端读取 `TUSHARE_TOKEN`，只实现已验证可用的股票主数据、日线和复权能力；无权限接口不得自动调用。
- `lib/data/quality.ts`：覆盖率、新鲜度、价格差异、方向一致率和来源选择的纯函数。
- `lib/data/market-pipeline.ts`：负责重试、并发限制、主备调用和质量决策，不承担指标计算。
- `lib/jobs/runner.ts`：调用行情管线并把质量结果写入现有快照、复盘和任务日志。

## 数据保存与页面状态

继续使用 `breadth_snapshots` 和 `daily_reviews` 保存业务结果，新增 `market_source_audits`：

- `trade_date`
- `snapshot_time`
- `source`
- `market_time`
- `received_at`
- `raw_count`
- `valid_count`
- `invalid_count`
- `coverage_pct`
- `direction_agreement_pct`
- `breadth_difference`
- `status`
- `message`

唯一键为 `(trade_date, snapshot_time, source)`，保证任务重跑只更新原记录。

页面统一展示：数据来源、市场时间、更新时间、完整/部分/失败/已核验状态。状态不是 `complete` 或 `verified` 时显示原因。失败节点显示“数据暂缺”，不显示上一交易日值。

## 重试与保护

- 普通盘中请求失败后重试两次，间隔分别为1秒和3秒。
- 腾讯请求分批执行，并发上限4；单批失败只重试该批。
- 来源返回空数组、代码重复异常、价格非数字或覆盖率不足均视为数据失败，而不是正常零值。
- Tushare Token只存在 `.dev.vars` 或托管环境 Secret 中，不出现在客户端、日志、错误信息或Git记录中。
- 任一公开行情接口字段变化时，对应映射测试必须先失败；在修复前该来源自动降级为不可用。

## ETF处理

- ETF目录与分类每日首次访问时由东方财富刷新并缓存。
- 当前分时、日K、周K、月K继续按需获取，不在后台批量抓取所有ETF分钟数据。
- 腾讯只校验所选ETF的最新价和涨跌幅，避免为全部ETF产生大量请求。
- ETF数据没有 Tushare盘后校正权限时，页面显示“东方财富／腾讯交叉校验”，不得显示“Tushare已核验”。

## 测试与验收

- 使用固定样本验证东方财富与腾讯字段映射、沪深京代码转换和ST剔除一致。
- 验证批量请求每批不超过60只、并发不超过4。
- 验证覆盖率、延迟、价格差异、方向一致率及三种状态边界。
- 验证主源失败时腾讯可独立生成“部分”快照，双源失败时不写入旧数据。
- 验证16:10生成即时复盘、17:20用Tushare重算后变为“已核验”。
- 验证重复任务只更新同一唯一键。
- 验证Token不出现在渲染HTML、API响应、日志及Git跟踪文件中。
- 本机连续完成一个交易日六次快照和一次盘后校正后，才把演示状态切换为真实数据状态。

## 实施顺序

先实现并验证本数据管线，再继续执行已经批准的 ETF“我的自选”功能计划。这样自选ETF添加后直接使用经过质量标记的真实行情，而不需要二次改造。
