# PanLayer 侧栏数据进度卡设计

## 目标

把现有侧栏“数据状态”卡升级为紧凑的任务进度入口，让用户无需离开当前页面即可判断哪些数据完整、哪些仍在更新，以及失败原因。

## 默认紧凑状态

卡片保持当前宽度与暗色视觉，不改变侧栏结构。默认显示：

- 总体状态：完整、部分、更新中或失败。
- 总进度：已完成任务数 / 当日应执行任务数。
- 一条总体进度条。
- 两项关键摘要：
  - 盘中快照完成节点数，例如 `4 / 6`。
  - 新高初始化完成数量与覆盖率，例如 `124 / 5317 · 2.33%`。
- 当前数据来源和最近更新时间。
- “查看详情”按钮与展开指示图标。

总体进度只统计当天当前时间之前已经到达执行时间的任务，避免把尚未到时间的任务误判为未完成。

## 展开详情

点击卡片或“查看详情”后，在卡片内部向上展开任务列表，再次点击收起。列表包含：

- 盘中快照：六个节点的完成数量和缺失节点。
- 收盘复盘：总体状态、已完成阶段数、下一次补跑时间或失败原因。
- 新高初始化：完成数、目标数、覆盖率及失败股票数。
- 盘前早参：等待、执行中、部分、完成或失败，以及实际完成时间。
- ETF 指标：等待、执行中、部分、完成或失败，以及更新时间。

每个任务使用统一颜色：

- 灰色：等待。
- 蓝橙色：执行中。
- 黄色：部分。
- 绿色：完成。
- 红色：失败。

展开区域使用有限高度和内部滚动，避免遮挡侧栏底部的账号与退出入口。

## 数据来源与刷新

组件只消费现有 `DailyJobHealth` 和 `NewHighProgress` 数据，不生成进度、不推测任务状态。页面数据刷新后，侧栏进度同步更新。

总进度的计算规则：

- 到达预定时间且状态为 `complete` 的任务计为完成。
- `partial`、`running`、`failed` 计入应执行总数，但不计为完成。
- 尚未到达执行时间的任务显示为等待，不计入当前总进度分母。
- 新高初始化作为持续后台任务单独显示数量和覆盖率，不把股票数量混入每日任务完成数。

## 交互与可访问性

- 使用原生按钮控制展开与收起。
- 设置 `aria-expanded` 和明确的中文标签。
- 键盘可以操作。
- 展开图标随状态旋转。
- 移动端侧栏行为保持不变。

## 测试

- 验证默认状态包含总体进度、盘中节点和新高覆盖率。
- 验证展开状态包含收盘复盘、早参、ETF 和失败原因。
- 验证尚未到执行时间的任务不进入总进度分母。
- 验证完成、部分、失败和执行中状态的文案映射。
- 验证按钮具有 `aria-expanded`。
